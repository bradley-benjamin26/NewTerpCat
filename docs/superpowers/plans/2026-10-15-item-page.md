# Item Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every search result gets its own page, `/item/<id>`, with where to find the book, its call number and its full catalog details.

**Architecture:** `sru.py` gains `_details(rec)` (extra MARC fields) and `record(xml, library)` (first record, full). `main.py` adds `GET /record/{id}`, which validates the ID and makes one `alma.mms_id=` SRU call to UMD or one Big Ten catalog. The frontend adds the server-rendered route `app/item/[id]/` and points result titles at it.

**Tech Stack:** FastAPI + httpx + pytest (Python 3.13, uv); Next.js + Vitest + Testing Library + axe-core.

**Spec:** `docs/superpowers/specs/2026-10-15-item-page-design.md`

## Global Constraints

- TDD: write each test, see it fail, then implement. Never rewrite a test to make it pass (AGENTS.md).
- WCAG 2.2 AA; the item page is covered by an axe check.
- IDs: `<digits>` for UMD, `<key>:<digits>` for a Big Ten library (`key` from `BTAA`). Anything else: 404.
- Copy, exactly:
  - 404 (API detail): `We couldn't find that record.`
  - 404 (page): `We couldn't find that record. It may have been removed from the catalog. Search again above.`
  - Catalog failure: `The library catalog is not responding. Try again shortly.`
  - Big Ten-only, available: `Not held at UMD. <Library> has a copy: request it through interlibrary loan.`
  - Big Ten-only, not available: `Not held at UMD. <Library> has it, but no copy is available right now.`
  - Catalog link: `Open in the UMD catalog`
  - Section headings: `Where to find it`, `Summary`, `Details`, `Subjects`, `Contents`, `Notes`
  - Detail labels: `Published`, `Edition`, `Description`, `Series`, `ISBN`, `Other authors`
- Style: existing tokens in `globals.css` only (system font, `--accent`, `--border`, `--focus`, dark mode). No cards, eyebrow labels or new colors.
- Next.js in this repo differs from older versions: read `frontend/node_modules/next/dist/docs/` before writing route code (see `01-app/01-getting-started/10-error-handling.md` for `notFound`).
- Run backend tests with `cd backend && uv run pytest`; frontend with `cd frontend && npx vitest run`.

## Review Focus

1. The ID reaches the page still URL-encoded (`rutgers%3A991234`) or decoded (`rutgers:991234`), depending on how Next hands over `params`: both must fetch `/record/rutgers%3A991234` (Task 3 test).
2. A Big Ten catalog answers with an HTML maintenance page instead of SRU XML: 502 with the catalog message, not a 500 (Task 2 test).
3. A malformed ID such as `%E0%A4%A` (bad percent-encoding) in the URL: the page shows the not-found state instead of crashing (Task 3 test).
4. A UMD holding with no call number: no empty call number line (Task 3 test).
5. An ID that looks valid but has CQL in it (`123 OR alma.all_for_ui=x`, `rutgers:1 OR 1`): 404 and no SRU call (Task 2 test).

### Task 2: `GET /record/{id}` (`main.py`)

**Files:**
- Modify: `backend/app/main.py`
- Test: `backend/tests/test_main.py`

**Interfaces:**
- Consumes: `record(xml, library)` from Task 1; `fetch(cql, base_url)` (already imported as `fetch`); `BTAA`.
- Produces: `GET /record/{id}` → 200 with the Task 1 record dict; 404 `{"detail": "We couldn't find that record."}`; 502 `{"detail": "The library catalog is not responding. Try again shortly."}`.

- [ ] **Step 1: Write the failing tests** in `test_main.py` (monkeypatch `main.fetch` as the search tests do; load the Task 1 fixture)
  - `test_record_fetches_a_umd_record_by_id`: the fake fetch records `(cql, base_url)`; GET `/record/990036740560108238` → 200, `title` and `publication` from the fixture, fetch called once with `cql == "alma.mms_id=990036740560108238"` and UMD's base URL (the default: call `fetch(cql)` with no base URL for UMD, or assert whichever you pass is `UMD["base_url"]`).
  - `test_record_fetches_a_big_ten_record_from_its_library`: GET `/record/rutgers:990036740560108238` → 200, `id == "rutgers:990036740560108238"`, fetch called with Rutgers' `base_url`.
  - `test_record_rejects_bad_ids_without_searching` (parametrize): `harvard:123`, `abc`, `123 OR alma.all_for_ui=x`, `rutgers:1 OR 1`, `rutgers:` → each 404 and the fake fetch is never called.

  - `test_record_reports_a_catalog_failure`: fake fetch raises `httpx.ConnectError("down")` → 502 with the catalog message; a second case returns `b"<html>maintenance</html>"` → also 502.

- [ ] **Step 3: Implement the endpoint.** Validate with `re.fullmatch(r"(?:([a-z]+):)?(\d+)", id)` and a key lookup in `{lib["key"]: lib for lib in BTAA}`. Catch `httpx.HTTPError` and `ET.ParseError` → 502.

### Task 3: Item page and result links (frontend)

**Files:**
- Create: `frontend/app/item/[id]/page.tsx`, `frontend/app/item/[id]/not-found.tsx`, `frontend/app/item/item.module.css`
- Modify: `frontend/app/ResultsList.tsx` (export `CatalogRecord`, `Holding` and `STATUS`; title links to `/item/${encodeURIComponent(r.id)}`)
- Modify: `AGENTS.md` Directories (add `app/item/` and its files; the backend `GET /record` goes in the `app/main.py` line)
- Test: `frontend/tests/itemPage.test.tsx`, `frontend/tests/search.test.tsx`

**Interfaces:**
- Consumes: `GET ${API_URL}/record/<encoded id>` from Task 2. `type Item = Omit<CatalogRecord, "score" | "breakdown"> & { publication: string | null; edition: string | null; description: string | null; series: string | null; summary: string | null; isbns: string[]; contributors: string[]; contents: string[]; notes: string[] }`.
- Produces: `export default async function ItemPage({ params }: PageProps<"/item/[id]">)` and `export async function generateMetadata(...)` returning `{ title: "<title> – NewTerpCat" }`. One `cache()`d (React) `getItem(id)` shared by both so the API is called once per request; it returns the item, `null` for 404, or throws/returns a failure marker for other errors (your choice, tested only through the page).

- [ ] **Step 1: Write the failing tests** in `itemPage.test.tsx` (stub `fetch` as `searchPage.test.tsx` does; reuse its `expectNoAxeViolations` pattern from `search.test.tsx`). A `full` item: the Task 1 fixture values, `url: "https://example.org/umd"`, `online: true`, `umd: true`, `btaa: []`.
  - `renders where to find it first, then the details`: headings in order are h1 title, then h2 `Where to find it`, `Summary`, `Details`, `Subjects`, `Contents`, `Notes`; the text `SH371 .K44 2020` and `Available online` appear inside the "Where to find it" region; a link named `Open in the UMD catalog` points to the `url`; the `Details` list has `Published` → `Baltimore : Johns Hopkins University Press, 2020` and `ISBN` → both ISBNs; no axe violations.
  - `leaves out sections and details the record does not have`: an item with every detail empty/null shows no `Summary`, `Subjects`, `Contents`, `Notes` headings and no `Edition` term.
  - `says a Big Ten-only book is not held at UMD`: `umd: false`, `url: null`, `btaa: [{ name: "Rutgers University", region: "east_coast", available: true }]` → text `Not held at UMD. Rutgers University has a copy: request it through interlibrary loan.` and no `Open in the UMD catalog` link; with `available: false` → `Not held at UMD. Rutgers University has it, but no copy is available right now.`
  - `skips the call number line when a holding has none`: holding `{ location: "McKeldin Library", call_number: null, status: "available" }` → `Available at UMD: McKeldin Library` and no empty call number element.
  - `fetches the record by its encoded ID` (parametrize): params `id` of `rutgers:991` and `rutgers%3A991` both fetch a URL ending `/record/rutgers%3A991`.
  - `shows not found for a missing record`: API 404 → `ItemPage(props)` rejects with Next's not-found error (assert `rejects.toThrow()` and the error's `digest` starts with `NEXT_HTTP_ERROR_FALLBACK;404`, or whatever this Next version's `notFound` throws; check the docs). Also for the malformed param `%E0%A4%A`, without calling the API.
  - `not-found page explains and offers the search box`: render `not-found.tsx` → the 404 page copy and a search box (`getByRole("searchbox")` or the `SearchForm` label).
  - `shows an alert when the catalog fails`: API 502, and fetch rejecting → `role="alert"` with the catalog message.
  - `page title names the book`: `generateMetadata` → `The Chesapeake oyster : a history – NewTerpCat`.
  - In `search.test.tsx`, `result titles open the item page`: a result with `id: "rutgers:991"` has a title link with `href` `/item/rutgers%3A991`.
  - In `search.test.tsx`, `results list announces the count and shows each record` (line ~82) asserts the title link is `https://example.org/1`. The spec changes that behavior, so change only that expectation to `/item/1` (approved by the user with this plan; not a test rewritten to pass).
